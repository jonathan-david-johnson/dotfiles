# Reference documents

Use this module for technical reference pages, configurations, commands, APIs, structured records, and reusable knowledge-base material.

## Structure

- Start with what the item is for and when to use it.
- Organize sections around the reader's lookup task, not the author's implementation sequence.
- Put constraints, defaults, scope, and compatibility information near the item they qualify.
- Use tables only when readers need to compare consistent fields across several items. Do not use a table for long prose or a one-item explanation.
- Keep names, capitalization, values, and units exact.
- Mark literals with code formatting: commands, file paths, class names, field names, IDs, status codes, and sample output.
- Distinguish required values, optional values, defaults, examples, and prohibited values.
- Provide examples that are valid, minimal, and labeled with their purpose.

## Links and cross-references

- Make the link text identify its destination or outcome.
- Link to the most specific useful target.
- Explain why a reader should follow a cross-reference if that is not obvious.
- Do not rely on a URL alone to communicate meaning.

## Images and diagrams

- Include a visual only when it adds information that prose cannot convey efficiently.
- Give images descriptive alternative text or adjacent explanatory text.
- Ensure diagrams label important actors, flows, boundaries, and states.
